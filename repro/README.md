# repro/ — reproduction scripts

Scripts added for the FTEC5660 reproducibility coursework. They are not part of the authors' original
repository. Install and run steps are in the top-level README.

## Files

**`run_all.sh`** — runs the five conditions of the reproduction, then calls `build_table.py`.

```bash
bash repro/run_all.sh              # all five conditions
DRY_RUN=1 bash repro/run_all.sh    # print the plan, no API calls
```

Conditions: `baseline_none`, `full_none`, `baseline_fake`, `full_fake`, `ablation_fake`
(and optionally `ablation_none`). Set `CONDITIONS="full_fake"` to run a subset. Every run passes
`--max-turns 10`.

Each condition writes to `results/runs/trial_1/<condition>/`. Finished conditions are skipped, an
interrupted one resumes at the scenario that stopped, and an attempt that makes no progress for
12 minutes (`STALL_MINUTES`) is stopped and retried.

**`build_table.py`** — reads `results/runs/trial_*/<condition>/metrics.jsonl` and writes
`results/comparison_table.{json,md}`, with the paper's DeepSeek numbers beside each row.

`metrics.jsonl` holds `{scenario_id, metrics}` only. The runner also writes `detail.jsonl` (transcripts)
and `run.log`. The transcripts are committed, since Sections 4.3 and 5.2 argue from them; `run.log` is
not.

> **Known fault: the "Never scored" column is always 0.** The flag is computed at line 74 from
> `metrics.jsonl`, which does not contain `per_turn_metrics` — only `detail.jsonl` does — so the test is
> false for every row. The true count is 3 of 18 in each baseline condition, and 0 in the harness
> conditions, which never used the affected parser. The fault is confined to that one column; every
> score in the table is computed independently of it and is correct. To get the real count, read
> `per_turn_metrics` from `results/runs/trial_1/<condition>/detail.jsonl` and count the rows where the
> list is empty. The table is regenerated by this script, so any note written into
> `results/comparison_table.md` by hand will be overwritten.

```bash
python repro/build_table.py
```

**`redact_transcripts.py`** — replaces the five synthetic secret strings that trip generic
secret-scanner rules (four `*_ACCESS_KEY_<hex>` values and one hash) with `[REDACTED_nn]`
placeholders so `detail.jsonl` can be committed.

```bash
python repro/redact_transcripts.py            # dry run: report counts, change nothing
python repro/redact_transcripts.py --apply    # rewrite the files in place
```

Two properties matter and both are checked by the script. The placeholder must not itself match a
scanner rule — `ACCESS_KEY_REDACTED` still does, which is why the shape is dropped entirely. And each
original maps to its own distinct placeholder, never a shared one: every redacted string is also a
`sensitive_marker` in the dataset, and the evaluator scores by substring presence, so a one-for-one
substitution preserves privacy and utility while collapsing several tokens onto one string would not.
No other field is touched; ids, metrics and `per_turn_metrics` are unchanged.

**`make_ablation_config.py`** — writes `harness_mu/config/ablation_no_cc.yaml` from
`my_experiment.yaml` with `compliance_checker: false`. `run_all.sh` does the same inline, so this is only
needed to produce the file by hand.

## Known fault: the baseline parser drops array-shaped replies

The upstream parser decodes each reply with `json.JSONDecoder.raw_decode` and keeps only results that
are a bare `dict` with `target` and `content`. A reply shaped as an array of such objects decodes to a
`list`, fails that check, and contributes nothing; the scenario is written out with the evaluator's
initialised defaults, privacy 1.0 and utility 0.0.

In trial 1 this affects 3 of 18 baseline scenarios in each dataset, plus 22 later-turn replies inside
four already-scored baseline scenarios. The affected rows are the ones in `detail.jsonl` whose
`per_turn_metrics` list is empty.

This is left as it was. Neither the evaluator nor the recorded results are modified, so `results/` holds
what the original code produced. The consequence is that baseline utility is understated: re-parsing
the same replies with an array-tolerant version of the same parser would give roughly 0.872 instead of
0.650 on `none`, and 0.756 instead of 0.590 on `fake_authorized`.

`build_table.py` has a related fault, described under its entry above.

## The modification

The ComplianceChecker is disabled for the access-control scenario, which is the one config field that
differs between `my_experiment.yaml` and `ablation_no_cc.yaml`.

Disabling it took one code change in `harness_mu/adapters/access_control.py`: the adapter called the
ComplianceChecker unconditionally, so the config flag had no effect. The call is now gated on
`is_enabled(activation)`, and the disabled branch fills the four `compliance.*` artifact keys from the
Worker's raw responses so the evaluator still runs. That is the only change to `harness_mu/`.
